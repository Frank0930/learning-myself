兩種呼叫方式：「手動」指使用者主動呼叫，用來組織流程；「自動可用」指使用者也能呼叫，代理人遇到符合情境的任務亦可採用。官方機制見 Skill mechanics。

工程：手動呼叫

技能設計用途／何時使用
ask-matt不知道該走哪個技能或流程時，先請 router 指路。
grill-with-docs需求或專案術語未對齊時，透過追問釐清，更新共用語言和決策紀錄。
triage需要將 issue 經過明確的分流狀態與角色時。
improve-codebase-architecture想定期盤點程式庫，找出值得深化的模組邊界時。
setup-matt-pocock-skills新 repository 首次採用這套工程技能時，設定 issue tracker 等共用約定。
to-spec討論已有共識，需要將它整理為正式規格並發佈時。
to-tickets規格或計畫太大，需要拆成可追蹤且標明依賴的小任務時。
implement規格或 tickets 已準備好，需要驅動實作、測試與完成前審查時。
wayfinder工作大到跨多個 agent session，先建立決策地圖與逐步解決路徑時。

prototype需要用可丟棄的原型回答狀態邏輯或 UI 方案問題時。

常見組合

新功能：grill-with-docs → to-spec → to-tickets → implement；implement可在適合的位置使用 tdd，並以 code-review收尾。疑難 bug：diagnosing-bugs先定位，再以測試固定修正。架構問題：improve-codebase-architecture找候選，再用 codebase-design討論介面與接縫。這些是依官方職責整理的情境示例，實際順序仍由當前瓶頸決定。

讀一份 SKILL.md 時看什麼

先看 YAML frontmatter 的 name、description與可能出現的 disable-model-invocation；再看正文的觸發情境、步驟、依條件載入的參考文件與可檢查的完成標準。官方 mechanics解釋呼叫設計，writing-for-agents解釋寫法原則。
