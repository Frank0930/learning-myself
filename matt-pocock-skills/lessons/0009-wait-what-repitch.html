wait-what：聽不懂就讓 agent 退一步重講

對話中有一句話沒聽懂時，直接叫停。這個技能要求 agent 補上缺少的背景，改用清楚的語言重講剛才的意思。

什麼時候用？

Matt 在 AI Hero 的說明建議：當你發現自己開始略過 agent 的說明、看不懂縮寫、或不知道結論的前提從哪裡來，就主動呼叫 /wait-what。官方 SKILL.md非常短，要求 agent 補少量背景、用簡明技術英文重講，並盡量使用專案 GLOSSARY.md 中已建立的詞彙。沒有 glossary 時，仍可重講。

和「簡短一點」的差別：你失去的是理解，不一定是耐心。只刪字可能連關鍵前提一起刪掉；wait-what要求補回前提，再把說明改得容易懂。這是Matt 對技能名稱的解釋。

一個可立即使用的句子

/wait-what

如果 agent 把退款決策說成「這條路徑由 materialization cascade 經 adapter seam 收斂」，你不必猜那些詞。呼叫後，好的回應會說明「我們現在談的是哪個退款步驟、這些詞對應到專案中的什麼概念，以及原結論為何成立」。

wait-what修補的是目前這一次說明。若團隊反覆對同一術語各說各話，Matt 建議用 grill-with-docs建立共用語言。

實戰題：判斷修補哪個問題

請看兩個情境：

  1. agent 剛解釋完退款流程，你不知道它為何假設收件人沒有退款權限。
  2. 產品、客服與工程師長期把「顧客」用來指不同角色，每次會議都因此誤會。

哪個情境適合立刻使用 /wait-what？另一個更適合哪個你已學過的技能？請再說一句：對第一個情境，好的重講應該補上什麼，而不只是把句子縮短。
