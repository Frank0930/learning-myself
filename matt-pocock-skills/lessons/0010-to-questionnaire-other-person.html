to-questionnaire：答案在別人手裡

當一項決策需要另一位領域專家的知識，先把問題整理成對方能填寫的文件，再帶答案回到原本的討論。

先找答案在哪裡

Matt 的 AI Hero 說明用答案的所在位置區分技能：答案在你心裡但尚未想清楚，可用 grill-me；答案在另一個人的經驗或權限裡，就用 to-questionnaire。它會建立一份 Markdown 問卷，供那個人非同步填寫，或在會議中一起完成。

先問寄送條件：官方技能原檔要求 agent 先向你確認兩件事：問卷交給誰，以及你需要對方回答哪些具體決策或事實。它不會要你先替對方解答未知的主題。

問卷要讓對方能回答

官方技能會在目前目錄寫出 to-questionnaire-<slug>.md。文件交代目的、背景、如何作答，再按重要性排列問題；每題只問一件事，留回答位置，最後提供補充欄位。它一次寫給一位收件者，不會自行寄出。即使對方只能回答一部分，或明確寫「不知道」，也比猜測有用。這些做法見原檔與Matt 的說明。

和前面的退款案例接起來

你與 agent 已釐清付款者、收件人的術語，但「收件人是否能要求退款」由商務負責人決定。此時繼續向你追問可能沒有答案。可以使用 to-questionnaire，告訴 agent 問卷是給商務負責人，且你需要對方決定退款資格與例外情況。收到回覆後，再回到 grill-with-docs 或 to-spec 整合決策。

中途遇到外部決策怎麼辦？grill-with-docs所用的 grilling每輪會一起問所有「前提已確定」的問題，不必等商務負責人回答才能討論與該答案無關的問題。對同一位商務負責人已知要問的多個問題，可交給 to-questionnaire做成一份 Markdown 問卷；它是靜態清單，不會預先猜出只有收到前置答案後才知道如何提問的分支。詳見 Matt 的「Common questions」。

實戰題：告訴 agent 這份問卷要做什麼

假設你是工程師，正在設計「禮物訂單退款」。你不能自行決定退款政策；商務負責人有權決定。你要請 to-questionnaire 幫你寫一份問卷給她。

請只回答兩件事：

  1. 問卷交給誰？
  2. 你需要她決定哪一個退款規則？

例如用「收件者：……；需要決定：……」回覆即可。你不用自己寫問卷題目；那是技能接下來要做的事。我會看你提供的資訊是否足夠讓 agent 動筆。
