讀懂 SKILL.md 的兩層結構

上一課你已能把「釐清需求 → 規格 → 任務」串起來。這次要從檔案本身看出技能為何在某個時機出現，以及出現後會怎麼工作。

第一層：frontmatter 是入口

SKILL.md 開頭兩條 --- 之間是 YAML frontmatter。官方 to-spec 原檔有 name、description和 disable-model-invocation: true。這代表它由使用者主動選用；描述是給人看的用途摘要。相對地，官方 tdd 原檔沒有這個停用欄位，描述列出「想以測試優先建立功能或修 bug」等觸發情境，讓 agent 也能依任務採用。詳細機制見官方 Skill mechanics。

快速判讀：先找 disable-model-invocation。有 true：人是入口；沒有：agent 也可能依 description 找到它。兩者都可以由人直接指定。官方 Skill mechanics 的寫法是省略該欄位，不是要求寫成 false。

第二層：正文是工作方法

Frontmatter 告訴你何時進門；正文告訴 agent 進門後怎麼做。例如 to-spec要求查看程式庫、確認測試接縫、按模板產出規格並發佈到專案 issue tracker。你的「把共識變成文檔」方向正確；原技能的交付物更精確地說，是發佈到追蹤系統的規格。接著 to-tickets把規格拆為帶有依賴關係的任務。

閱讀正文時先找三件事：輸入從哪裡來，動作依什麼順序做，完成標準如何判斷。日後設計自己的技能時，這三件事能幫團隊知道它是否可執行、可驗證。官方 writing-for-agents進一步討論清楚的完成標準。

實戰題：向團隊解釋一個陌生技能

同事寫了一個技能，開頭如下（教學示意）：

---
name: incident-review
description: 分析已發生的服務事故，找出根因並產出後續行動。
disable-model-invocation: true
---

請回答兩件事：① 依這份 frontmatter，誰能啟動它？② 如果團隊希望 agent 在使用者說「幫我回顧昨天的事故」時也能主動採用，應改哪裡？請說明原因，不必寫完整技能。

請把答案回覆給我；我會指出判讀是否正確，並用下一課帶你看好技能的觸發條件與完成標準。任何句子不清楚，也請直接追問。

延伸閱讀

讀 官方 Skill mechanics 的 Invocation 小節，再對照 to-spec 和 tdd 的開頭。複習時用SKILL.md 結構速查。
